Bony Tony: The Revenge

Play as concrete-shoed Bony Tony and take revenge on the mafia who sunk you in the sea. Use a shotgun to blast yourself to the top of their headquarters and take out the boss.

Bony Tony is a platformer where your main mode of movement is by shooting, which launches your character in the opposite direction. You can reload on the ground, or chain reloads in the air by shooting enemies.

    • Physics

    The physics for this game had to be written from scratch since our engine had no system or library in place. This meant deciding what type of collision shapes we wanted to support and making sure we got necessary data back when objects collided.

    Designing this meant deciding on some constraints to make the implementation as simple as it needed to be. Since all gameplay would exist on a singular 2D plane, this meant all physics could be checked in 2D as well. Another early decision I made was that the game would only support collisions using axis aligned bounding boxes or rays.

    I needed information from collisions such as the normal and point of collision. As such I felt the best check to use for the player was a swept AABB collision. This was done by checking the collision as a ray vs aabb, using the Minkowski sum of both boxes. A separate test project was made where I could test and verify the math before it was implemented in the game. 

    
// Returns a number between 0 and 1 representing where along the line a collision occurred. Returns -1 on no collision.

inline float AABBLineCollision(const AABB& aAABB, const Ray& aRay)
{
	float tMin = 0.f;
	float tMax = 1.f;

	const float topCornerPositionX = aAABB.position.x - aAABB.size.x * 0.5f;
	const float topCornerPositionY = aAABB.position.y + aAABB.size.y * 0.5f;
	Tga::Vector2f lineStart = aRay.origin;
	Tga::Vector2f lineDirection = aRay.direction.GetNormalized() * aRay.magnitude;

	if (abs(lineDirection.x) < FLT_EPSILON)
	{
		if (lineStart.x < topCornerPositionX ||
                    lineStart.x >  topCornerPositionX + aAABB.size.x)
		{
			return FLT_MAX;
		}
	}
	else
	{
		float t1 = (topCornerPositionX - lineStart.x) / lineDirection.x;
		float t2 = (topCornerPositionX + aAABB.size.x - lineStart.x) / lineDirection.x;
    
		if (t1 > t2)
		{
			std::swap(t1, t2);
		}
    
		tMin = std::max(tMin, t1);
		tMax = std::min(tMax, t2);
    
		if (tMin > tMax)
		{
			return FLT_MAX;
		}
	}
	if (abs(lineDirection.y) < FLT_EPSILON)
	{
		if (lineStart.y > topCornerPositionY ||
                    lineStart.y < topCornerPositionY - aAABB.size.y)
		{
			return FLT_MAX;
		}
	}
	else
	{
		float t1 = (topCornerPositionY - lineStart.y) / lineDirection.y;
		float t2 = (topCornerPositionY - aAABB.size.y - lineStart.y) / lineDirection.y;
    
		if (t1 > t2)
		{
			std::swap(t1, t2);
		}
    
		tMin = std::max(tMin, t1);
		tMax = std::min(tMax, t2);
    
		if (tMin > tMax)
		{
			return FLT_MAX;
		}
	}
	return tMin;
}

    Animation Implementation

    I was responsible for implementing most non procedural animations. In this engine that meant loading the animation data for a specific model and controlling its animation state manually in code. The Game Engine has as part of its API a basic animation controller, but it is up to the programmer to handle the state of what to play when, as well as how animations are stored and managed.

    A category of animated objects in the game are the animated props that are placed as set dessing in the game's levels. Prop animations had behaviours such as looping forever from start, and playing when shot every time—or only the fist time.
